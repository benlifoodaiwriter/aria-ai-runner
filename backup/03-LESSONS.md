- پاسخ همیشه **فارسی**، ساده و بدون اصطلاح فنی بی‌توضیح. کاربر برنامه‌نویس نیست.

- کاربر واژه‌های دقیق رابط را به کار می‌برد؛ همان‌ها را استفاده کنید: «مسیر راه»، «مقالات تکراری و شبه تکراری»، «رفع هم نوع خواری»، «هوش مصنوعی با API»، «اشتراکی»، «جمع آوری اطلاعات»، «راهنمایی».

- هرگز: جمع‌آوری رمز یا کوکی، اسکرپ نتایج گوگل، دور زدن محدودیت شبکه، اعمال تغییر روی سایت بدون تأیید کاربر.

## ۵. تصمیم‌های کلیدی (و چرا)
- **Codex بدون npm** ← npm در سقف حافظه هاست اشتراکی می‌میرد.
- **auto = فقط CLI آزموده‌شده** ← CLI ناکارآمد همه چیز را متوقف می‌کرد.
- **اجراکننده عمومی + داده خصوصی** ← دقیقه رایگان Actions. داده و دانش رمزنگاری نشده‌اند، پس در مخزن خصوصی می‌مانند.
- **تبدیل خودکار مخزن به عمومی فقط با بررسی fail-safe** ← فقط پاسخ 404 قطعی یعنی «داده‌ای ندارد» (`holds_data()`).
- **اعلان‌ها روی جدول موجود `alerts`** (نوع از `kind_of()`) و جدول جدید ساخته نشد.
- **پیگیری‌ها در option** (حداکثر ۳۰۰) ← بدون migration.
- **رشته جمع `_n()` استفاده نشود** ← build ترجمه آن را نمی‌گیرد.
- **منو از یک منبع (`Admin::nav()`)** برای منوی وردپرس و سایدبار ← هم‌خوانی همیشگی.
- **تنظیمات به صفحه‌های جدا** (`settings-ai` و …). لینک‌های قدیمی `#/settings?tab=x` در `route()` به صفحه جدید نگاشت می‌شوند.
- **وقتی افزونه سئوی دیگری (Rank Math) فعال است** SEOlity متا را داخل همان می‌نویسد و تگ head تکراری چاپ نمی‌کند.

## ۶. محیط آزمایش (در کانتینر ابری پاک می‌شود؛ در صورت نیاز دوباره بسازید)
- قبلاً: MySQL + وردپرس روی `127.0.0.1:8899` (admin/admin123) با Rank Math و Elementor واقعی، یک mu-plugin برای fixtureها (پاسخ‌های ساختگی Anthropic با کلید `sk-ant-api03-TESTVALID`، SerpApi، Serper، Gemini) و اسکریپت‌های تست `ops-test`، `lifecycle-test`، `provider-test`، `rest`، `actions-test`، `imp-test`، `cli-arch-test` و `smoke.mjs` (Playwright). **همه پاک شده‌اند.**
- راه سریع‌تر برای آزمایش رابط بدون وردپرس (روش 1.15.0):
  1. با یک اسکریپت PHP که `__()` را از روی `fa-*.tsv` شبیه‌سازی می‌کند، `Admin::routes()/nav()/I18n::strings()` را به JSON تبدیل کنید.
  2. یک صفحه HTML بسازید که `editor.css`، `app.css`، `charts.js`، `ui.js`، `app.js` و همه `pages-*.js` را بار کند و `window.SEOLITY` را با آن JSON پر کند.
  3. با Playwright درخواست‌های `/wp-json/seolity/v1/*` را با داده نمونه جواب دهید (`page.route`)، و دسکتاپ (1440) و موبایل (390) را عکس بگیرید و خطاهای کنسول را بررسی کنید.
- Chromium و Playwright از قبل نصب‌اند: `require('playwright')`. دوباره نصب نکنید.
