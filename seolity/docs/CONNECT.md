### هوش مصنوعی با کلید API

#### Anthropic Claude API

`هوش مصنوعی` `پولی (پیش‌پرداخت)` `۵ دقیقه`

بهترین کیفیت برای بازنویسی محتوا، متا و تحلیل سئو (مدل‌های Claude). هزینه بر اساس مصرف از اعتبار پیش‌پرداخت کم می‌شود.

**پیش‌نیازها:** ایمیل و شماره موبایل برای ساخت حساب؛ کارت بانکی بین‌المللی برای خرید اعتبار

1. وارد کنسول Anthropic شوید و حساب بسازید (یا با گوگل وارد شوید). [باز کردن کنسول](https://console.anthropic.com/)
2. از بخش Billing اعتبار (Credits) بخرید. بدون اعتبار، کلید کار نمی‌کند و خطای credit balance می‌گیرید. ۵ تا ۱۰ دلار برای شروع کافی است. [صفحه Billing](https://console.anthropic.com/settings/billing)
3. به صفحه API Keys بروید و «Create Key» را بزنید؛ یک نام مثل SEOlity بدهید. [ساخت کلید API (لینک مستقیم)](https://console.anthropic.com/settings/keys)
4. کلید را که با sk-ant- شروع می‌شود همان لحظه کپی کنید؛ دوباره نمایش داده نمی‌شود.

   ```
   sk-ant-api03-…
   ```
5. در SEOlity: تنظیمات ← هوش مصنوعی ← «Anthropic API key» را بچسبانید و Save بزنید. سپس «ارائه‌دهنده» را Anthropic بگذارید، تنظیمات را ذخیره و «تست اتصال» را بزنید.

**رفع مشکل**

- **خطای credit balance is too low** — اعتبار حساب تمام شده یا نخریده‌اید. از صفحه Billing اعتبار اضافه کنید.
- **خطای 401 / invalid x-api-key** — کلید ناقص کپی شده یا حذف شده. یک کلید جدید بسازید و دوباره ذخیره کنید.
- **خطای 429 (rate limit)** — حساب‌های تازه سقف درخواست کمی دارند. چند دقیقه صبر کنید؛ با افزایش خرید، سطح حساب (tier) بالا می‌رود.

**مستندات رسمی:** [مستندات شروع API](https://docs.claude.com/en/api/overview) · [کشورهای پشتیبانی‌شده](https://www.anthropic.com/supported-countries) · [قیمت‌ها](https://www.anthropic.com/pricing#api)

#### OpenAI API (GPT)

`هوش مصنوعی` `پولی (پیش‌پرداخت)` `۵ دقیقه`

مدل‌های GPT از طریق API. توجه: اشتراک ChatGPT Plus/Pro شامل اعتبار API نیست؛ برای استفاده از اشتراک، راهنمای «اشتراک ChatGPT» را ببینید.

**پیش‌نیازها:** حساب OpenAI و کارت برای خرید اعتبار

1. وارد پلتفرم OpenAI شوید یا ثبت‌نام کنید. [ورود به پلتفرم](https://platform.openai.com/)
2. در Billing یک روش پرداخت اضافه کنید و اعتبار بخرید (حداقل ۵ دلار). [صفحه Billing](https://platform.openai.com/settings/organization/billing/overview)
3. در صفحه API keys روی «Create new secret key» بزنید. Permissions را All بگذارید (یا حداقل Model capabilities: Write). [ساخت کلید API (لینک مستقیم)](https://platform.openai.com/api-keys)
4. کلید (sk-…) را فوراً کپی کنید.

   ```
   sk-proj-…
   ```
5. در SEOlity: تنظیمات ← هوش مصنوعی ← «OpenAI API key» ← Save؛ ارائه‌دهنده را OpenAI بگذارید و تست بزنید.

**رفع مشکل**

- **خطای insufficient_quota** — اعتبار ندارید یا تمام شده. اشتراک ChatGPT برای API حساب نمی‌شود.
- **model_not_found** — نام مدل را در تنظیمات بررسی کنید یا خالی بگذارید تا پیش‌فرض استفاده شود. برخی مدل‌ها نیاز به تأیید سازمان دارند.

**مستندات رسمی:** [شروع سریع](https://platform.openai.com/docs/quickstart) · [کشورهای پشتیبانی‌شده](https://platform.openai.com/docs/supported-countries) · [قیمت‌ها](https://openai.com/api/pricing/)

#### Google Gemini API

`هوش مصنوعی` `سطح رایگان دارد` `۳ دقیقه`

ساده‌ترین راه شروع: کلید رایگان با سقف استفاده روزانه از Google AI Studio.

**پیش‌نیازها:** یک حساب گوگل

1. Google AI Studio را باز کنید و با حساب گوگل وارد شوید (شرایط را بپذیرید). [باز کردن AI Studio](https://aistudio.google.com/)
2. روی «Get API key» و سپس «Create API key» بزنید. اگر پروژه نداشتید، گزینه ساخت پروژه جدید را انتخاب کنید. [صفحه کلیدها (لینک مستقیم)](https://aistudio.google.com/app/apikey)
3. کلید (AIza…) را کپی کنید.

   ```
   AIzaSy…
   ```
4. در SEOlity: تنظیمات ← هوش مصنوعی ← «Google Gemini API key» ← Save؛ ارائه‌دهنده را Gemini بگذارید و تست بزنید.

**رفع مشکل**

- **User location is not supported** — Gemini فقط در کشورهای مشخصی ارائه می‌شود و درخواست از محل سرور هاست شما ارسال می‌شود. فهرست مناطق را ببینید یا ارائه‌دهنده دیگری انتخاب کنید.
- **خطای 429 / RESOURCE_EXHAUSTED** — سقف رایگان پر شده. صبر کنید یا Billing را در پروژه فعال کنید.

**مستندات رسمی:** [راهنمای کلید API](https://ai.google.dev/gemini-api/docs/api-key) · [مناطق در دسترس](https://ai.google.dev/gemini-api/docs/available-regions) · [سقف‌ها و قیمت](https://ai.google.dev/gemini-api/docs/pricing)

#### OpenRouter

`هوش مصنوعی` `پیش‌پرداخت + مدل‌های رایگان` `۵ دقیقه`

یک کلید برای صدها مدل (Claude، GPT، Gemini، Llama، DeepSeek، Qwen…). مدل‌هایی که آخرشان :free است رایگان‌اند (با سقف).

**پیش‌نیازها:** حساب OpenRouter (گوگل/گیت‌هاب/ایمیل)

1. در OpenRouter ثبت‌نام کنید. [باز کردن OpenRouter](https://openrouter.ai/)
2. برای مدل‌های غیررایگان از صفحه Credits اعتبار بخرید. [صفحه Credits](https://openrouter.ai/settings/credits)
3. در صفحه Keys روی «Create Key» بزنید و کلید (sk-or-…) را کپی کنید. [ساخت کلید (لینک مستقیم)](https://openrouter.ai/settings/keys)

   ```
   sk-or-v1-…
   ```
4. شناسه مدل دلخواه را از فهرست مدل‌ها کپی کنید (مثلاً anthropic/claude-sonnet-4.5 یا یک مدل :free). [فهرست مدل‌ها](https://openrouter.ai/models)
5. در SEOlity: تنظیمات ← هوش مصنوعی ← «OpenRouter API key» ← Save؛ ارائه‌دهنده را OpenRouter و مدل را وارد کنید و تست بزنید.

**رفع مشکل**

- **خطای 402** — اعتبار کافی نیست؛ اعتبار بخرید یا یک مدل :free انتخاب کنید.
- **پاسخ JSON نامعتبر** — مدل‌های خیلی کوچک گاهی خروجی ساختاریافته را خراب می‌کنند. یک مدل قوی‌تر انتخاب کنید.

**مستندات رسمی:** [شروع سریع](https://openrouter.ai/docs/quickstart) · [مدل‌ها و قیمت‌ها](https://openrouter.ai/models)

#### Ollama (local / self-hosted)

`هوش مصنوعی` `رایگان، بدون حساب` `۱۵ دقیقه`

مدل‌های متن‌باز روی سرور خودتان؛ بدون کلید، بدون ارسال داده به بیرون. نیاز به سرور با رم کافی (حداقل ۸ تا ۱۶ گیگ برای مدل‌های ۷ تا ۸ میلیارد پارامتری).

**پیش‌نیازها:** یک سرور یا کامپیوتر که وردپرس به آن دسترسی شبکه‌ای دارد

1. Ollama را نصب کنید (ویندوز/مک/لینوکس). روی لینوکس: [دانلود Ollama](https://ollama.com/download)

   ```
   curl -fsSL https://ollama.com/install.sh | sh
   ```
2. یک مدل دریافت کنید. برای فارسی مدل‌های Qwen یا Gemma گزینه‌های خوبی هستند: [کتابخانه مدل‌ها](https://ollama.com/library)

   ```
   ollama pull qwen2.5:7b
   ```
3. اگر وردپرس روی سرور دیگری است، Ollama را روی همه رابط‌ها در دسترس کنید و پورت 11434 را فقط برای IP سرور وردپرس باز کنید:

   ```
   OLLAMA_HOST=0.0.0.0:11434 ollama serve
   ```
4. در SEOlity: تنظیمات ← هوش مصنوعی ← ارائه‌دهنده Ollama، آدرس (مثلاً http://127.0.0.1:11434) و نام مدل (qwen2.5:7b) را وارد کنید، ذخیره و تست کنید.

**رفع مشکل**

- **Connection refused / timeout** — وردپرس به آدرس Ollama دسترسی ندارد. روی هاست اشتراکی معمولاً امکان‌پذیر نیست؛ از VPS استفاده کنید یا آدرس عمومی امن بدهید.
- **کند بودن پاسخ** — مدل کوچک‌تر یا سرور با GPU انتخاب کنید و «مهلت زمانی هوش مصنوعی» را در تنظیمات بیشتر کنید.

**مستندات رسمی:** [پرسش‌های متداول Ollama](https://github.com/ollama/ollama/blob/main/docs/faq.md)

#### API سفارشی (هر سرویس دلخواه)

`هوش مصنوعی` `هر سرویس سازگار` `۵ دقیقه`

هر سرویس هوش مصنوعی که API سازگار با OpenAI یا Anthropic دارد را با همان تنظیماتی که در مستنداتش آمده وصل کنید: DeepSeek، Groq، Mistral، Together، xAI، Perplexity، Azure OpenAI، Cloudflare Workers AI، LM Studio، vLLM، LiteLLM و درگاه‌های مشابه.

**پیش‌نیازها:** کلید API و آدرس پایه (Base URL) از مستندات سرویس

1. در «تنظیمات ← هوش مصنوعی» به کارت «API سفارشی» بروید و از فهرست «سرویس» سرویس خود را انتخاب کنید؛ آدرس، قالب، روش ارسال کلید و حالت JSON خودکار پر می‌شوند و لینک گرفتن کلید نمایش داده می‌شود.
2. سرویس در فهرست نیست؟ «Custom» را انتخاب کنید و Base URL را از مستندات سرویس بنویسید. نمونه‌ها:

   ```
   https://api.deepseek.com/v1
https://api.groq.com/openai/v1
https://generativelanguage.googleapis.com/v1beta/openai
https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/v1
https://{RESOURCE}.openai.azure.com/openai/deployments/{DEPLOYMENT}
http://localhost:1234/v1   (LM Studio)
   ```
3. «API format»: اگر مستندات از /chat/completions می‌گوید OpenAI-compatible، اگر از /v1/messages می‌گوید Anthropic-compatible. اگر آدرس کامل endpoint را دارید همان را بچسبانید؛ SEOlity تشخیص می‌دهد.
4. «How the key is sent»: بیشتر سرویس‌ها Bearer هستند؛ Azure از api-key، درگاه‌های Claude از x-api-key، و برخی از پارامتر URL (مثلاً key) استفاده می‌کنند. کلید را در فیلد API key ذخیره کنید.
5. «Fetch models» فهرست مدل‌های سرویس را می‌آورد؛ یکی را انتخاب کنید (برای Azure نام Deployment).
6. هدرهای اضافه (مثلاً HTTP-Referer)، پارامترهای کوئری (مثلاً api-version=2024-10-21 برای Azure)، پارامتر محدودیت توکن و دما در بخش «پیشرفته» هستند. پیش‌نمایش، درخواست دقیق را نشان می‌دهد.
7. «Test connection» و سپس «Use as AI engine» را بزنید. «Structured output» روی خودکار بماند: SEOlity به‌ترتیب json_schema، JSON mode و دستور در متن را امتحان می‌کند و حالت موفق را به خاطر می‌سپارد.

**رفع مشکل**

- **خطای 404** — Base URL اشتباه است؛ معمولاً /v1 جا افتاده یا اضافه است. پیش‌نمایش «Request URL» را با مستندات مقایسه کنید.
- **خطای 401 یا 403** — روش ارسال کلید اشتباه است (مثلاً Bearer به‌جای api-key) یا کلید اعتبار ندارد.
- **خطای response_format یا json_schema** — در حالت خودکار خودش حالت بعدی را امتحان می‌کند؛ اگر حالت را دستی گذاشته‌اید «JSON mode» یا «Instructions in the prompt only» را انتخاب کنید.
- **خطای max_tokens** — پارامتر محدودیت توکن را روی max_completion_tokens یا «ارسال نشود» بگذارید.
- **مدل‌های استدلالی پاسخ را با <think> برمی‌گردانند** — SEOlity بخش <think> را خودکار حذف می‌کند؛ دما را خالی بگذارید.
- **سرور محلی در دسترس نیست** — localhost یعنی همان سروری که وردپرس روی آن است؛ برای کامپیوتر دیگر آدرس شبکه آن را بدهید.

**مستندات رسمی:** [سازگاری Gemini با OpenAI](https://ai.google.dev/gemini-api/docs/openai) · [Workers AI سازگار با OpenAI](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/) · [مرجع Azure OpenAI](https://learn.microsoft.com/azure/ai-services/openai/reference)

### هوش مصنوعی با اشتراک (Claude / ChatGPT) از طریق GitHub

#### اشتراک Claude Pro / Max

`هوش مصنوعی اشتراکی` `بدون هزینه API` `۱۰ دقیقه`

از اشتراک Claude خودتان استفاده می‌کند (بدون خرید اعتبار API). درخواست‌ها روی GitHub Actions در مخزن خصوصی شما با Claude Code اجرا می‌شوند. صفحه «اکانت اشتراکی» همه مراحل را به ترتیب و با بررسی خودکار انجام می‌دهد.

**پیش‌نیازها:** اشتراک فعال Claude Pro یا Max؛ حساب GitHub رایگان؛ Node.js روی کامپیوتر خودتان (فقط یک‌بار برای گرفتن توکن)

1. صفحه «اکانت اشتراکی» را باز کنید و «Claude Pro / Max» را انتخاب کنید. مرحله ۰ (بررسی پیش‌نیازها) نشان می‌دهد چه چیزی مانده است.
2. مرحله ۱: GitHub را با یک توکن وصل کنید (لینک آماده با دسترسی‌های لازم) و «ساخت مخزن و نصب اجراکننده» را بزنید. [ساخت توکن GitHub (دسترسی‌ها از قبل انتخاب شده)](https://github.com/settings/tokens/new?scopes=repo,workflow&description=SEOlity)
3. روی کامپیوتر خودتان Node.js و Claude Code را نصب کنید: [دانلود Node.js](https://nodejs.org/en/download)

   ```
   npm install -g @anthropic-ai/claude-code
   ```
4. این دستور را بزنید؛ مرورگر باز می‌شود، با اکانت Claude Pro/Max وارد شوید و Authorize بزنید. توکن یک‌ساله (sk-ant-oat01-…) در ترمینال چاپ می‌شود:

   ```
   claude setup-token
   ```
5. مرحله ۳: توکن را بچسبانید و «ذخیره امن در GitHub Secrets» را بزنید. مرحله ۴: «ارسال درخواست تست» و سپس «استفاده به‌عنوان موتور هوش مصنوعی».

**رفع مشکل**

- **claude: command not found** — ترمینال را ببندید و باز کنید یا مسیر npm global را به PATH اضافه کنید.
- **Invalid API key / 401 در اجرای Actions** — توکن منقضی یا ناقص است؛ دوباره claude setup-token را اجرا و در مرحله ۳ ذخیره کنید.
- **پاسخ‌ها چند دقیقه طول می‌کشد** — طبیعی است (روشن شدن ماشین GitHub). با «کلادفلر» سریع‌تر و مطمئن‌تر می‌رسند.

**مستندات رسمی:** [توکن یک‌ساله claude setup-token](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token) · [Claude Code در GitHub Actions](https://code.claude.com/docs/en/github-actions)

#### اشتراک ChatGPT Plus / Pro (Codex)

`هوش مصنوعی اشتراکی` `بدون هزینه API` `۱۰ دقیقه`

از اشتراک ChatGPT شما با Codex CLI روی GitHub Actions استفاده می‌کند. ورود به‌طور خودکار تمدید و نسخه جدید ذخیره می‌شود.

**پیش‌نیازها:** اشتراک ChatGPT Plus، Pro، Team یا Business؛ حساب GitHub رایگان؛ Node.js روی کامپیوتر خودتان

1. صفحه «اکانت اشتراکی» را باز و «ChatGPT Plus / Pro» را انتخاب کنید؛ مرحله ۱ (GitHub و مخزن) را با یک کلیک انجام دهید.
2. Codex CLI را نصب کنید: [دانلود Node.js](https://nodejs.org/en/download)

   ```
   npm install -g @openai/codex
   ```
3. یک‌بار تنظیم کنید که ورود در فایل ذخیره شود (مک/لینوکس؛ دستور ویندوز در خود صفحه است):

   ```
   mkdir -p ~/.codex && echo 'cli_auth_credentials_store = "file"' >> ~/.codex/config.toml
   ```
4. وارد شوید و «Sign in with ChatGPT» را انتخاب کنید:

   ```
   codex login
   ```
5. کل محتوای auth.json را کپی کنید (ویندوز: %USERPROFILE%\.codex\auth.json) و در مرحله ۳ بچسبانید، سپس تست کنید.

   ```
   cat ~/.codex/auth.json
   ```

**رفع مشکل**

- **not valid JSON** — کل فایل را از { تا } کپی کنید، نه فقط یک بخش.
- **فایل auth.json ساخته نشد** — تنظیم cli_auth_credentials_store = "file" را انجام ندادید و ورود در Keychain سیستم ذخیره شد؛ تنظیم را اضافه و دوباره codex login کنید.
- **خطای ورود بعد از چند هفته** — SEOlity نسخه تمدیدشده را خودکار ذخیره می‌کند؛ اگر باز خطا داد، codex login را دوباره اجرا و فایل را دوباره ذخیره کنید.

**مستندات رسمی:** [احراز هویت Codex](https://github.com/openai/codex/blob/main/docs/authentication.md) · [مخزن Codex CLI](https://github.com/openai/codex)

### GitHub، کلادفلر، دانش و داده

#### GitHub

`لازم برای اشتراک، دانش و بایگانی` `رایگان` `۳ دقیقه`

یک توکن کافی است: SEOlity مخزن‌های خصوصی اجراکننده، دانش و داده را خودش با یک کلیک می‌سازد و تنظیم می‌کند.

**پیش‌نیازها:** حساب GitHub (رایگان)

1. حساب GitHub ندارید؟ رایگان بسازید. [ثبت‌نام در GitHub](https://github.com/signup)
2. این لینک را باز کنید؛ دسترسی‌های repo و workflow از قبل انتخاب شده‌اند. مدت اعتبار را انتخاب و «Generate token» را بزنید. [ساخت توکن (لینک مستقیم)](https://github.com/settings/tokens/new?scopes=repo,workflow&description=SEOlity)
3. توکن ghp_… را کپی کنید و در «GitHub و داده» ← مرحله ۱ بچسبانید و «اتصال و بررسی توکن» را بزنید.

   ```
   ghp_…
   ```
4. در مرحله ۲ «ساخت و راه‌اندازی همه‌چیز» را بزنید: یک مخزن خصوصی seolity-ai ساخته می‌شود که اجراکننده اشتراکی، دانش اختصاصی و بایگانی داده (شاخه seolity-data) را با هم دارد.
5. توکن محدودتر (Fine-grained) می‌خواهید؟ مخزن‌های خصوصی را اول خودتان بسازید و دسترسی Contents، Actions، Secrets و Workflows را Read and write بدهید. [ساخت توکن Fine-grained](https://github.com/settings/personal-access-tokens/new) · [ساخت مخزن جدید](https://github.com/new)

**رفع مشکل**

- **Bad credentials** — توکن ناقص کپی شده یا باطل/منقضی شده است. یک توکن جدید بسازید.
- **403 Resource not accessible by personal access token** — توکن Fine-grained یکی از دسترسی‌ها (معمولاً Secrets یا Workflows) را ندارد یا مخزن در فهرست آن نیست.
- **دقایق Actions تمام شده** — مخازن خصوصی سهمیه ماهانه دارند. مصرف را در Billing گیت‌هاب ببینید.

**مستندات رسمی:** [مستندات توکن‌های دسترسی](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) · [هزینه GitHub Actions](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions)

#### پایگاه دانش سئو

`اختیاری` `رایگان` `۱ دقیقه`

به‌طور پیش‌فرض SEOlity از دانش مشترک و رایگان استفاده می‌کند. با مخزن اختصاصی، دکمه «جمع‌آوری دانش الان» یک Workflow در گیت‌هاب اجرا می‌کند که منابع سئو، کوئری‌های سرچ کنسول، صفحات سایت و رقبای شما را با هوش مصنوعی (اشتراک Claude/ChatGPT یا کلید Anthropic) تحلیل می‌کند و یک «پلی‌بوک اختصاصی سایت» (استراتژی، موضوعات، کلمات کلیدی، رقبا) در گیت‌هاب می‌نویسد؛ هوش مصنوعی در همه تولیدها از آن استفاده می‌کند.

1. در «GitHub و داده» کارت «پایگاه دانش سئو» را پیدا کنید و «ساخت مخزن دانش اختصاصی» را بزنید؛ دانش فعلی، سازنده دانش و Workflow هفتگی در آن قرار می‌گیرد و SEOlity به آن وصل می‌شود.
2. هوش مصنوعی اشتراکی را مستقر کنید (یا کلید Anthropic را ذخیره کنید)؛ سازنده دانش از همان حساب استفاده می‌کند: CLAUDE_CODE_OAUTH_TOKEN، CODEX_AUTH_JSON یا ANTHROPIC_API_KEY.

   ```
   CLAUDE_CODE_OAUTH_TOKEN
   ```
3. در صفحه «پایگاه دانش» دکمه «جمع‌آوری دانش الان» را بزنید. وضعیت اجرا هر ۱۵ ثانیه به‌روز می‌شود و در پایان گزارش (منابع، اسناد ساخته‌شده، پلی‌بوک سایت) نمایش داده و دانش همگام می‌شود.
4. منابع دلخواه را در فایل sources.json مخزن اضافه کنید؛ «اجرای سازنده دانش» آن‌ها را خلاصه می‌کند و SEOlity همگام می‌شود.

   ```
   seolity/tools/knowledge-builder/sources.json
   ```

**رفع مشکل**

- **همگام‌سازی خطا می‌دهد** — توکن GitHub به مخزن دانش دسترسی ندارد یا نام شاخه/پوشه در تنظیمات پیشرفته اشتباه است.
- **سازنده دانش اجرا نمی‌شود** — هیچ‌کدام از Secretهای CLAUDE_CODE_OAUTH_TOKEN، CODEX_AUTH_JSON یا ANTHROPIC_API_KEY در مخزن نیست یا Actions غیرفعال است. اول هوش مصنوعی اشتراکی را مستقر کنید.

**مستندات رسمی:** [اسرار رمزنگاری‌شده در GitHub Actions](https://docs.github.com/en/actions/security-for-github-actions/security-guides/using-secrets-in-github-actions)

#### کلادفلر (رله سریع و زمان‌بند)

`اختیاری، پیشنهادی` `پلن رایگان` `۳ دقیقه`

یک ورکر رایگان روی حساب کلادفلر خودتان که SEOlity خودش مستقر می‌کند: پاسخ‌های هوش مصنوعی اشتراکی سریع‌تر می‌رسند (حتی برای سایت لوکال) و صف پس‌زمینه SEOlity هر چند دقیقه سر وقت اجرا می‌شود.

**پیش‌نیازها:** حساب رایگان کلادفلر (دامنه لازم نیست)

1. در کلادفلر ثبت‌نام کنید. [ثبت‌نام رایگان](https://dash.cloudflare.com/sign-up)
2. صفحه API Tokens ← Create Token ← کنار «Edit Cloudflare Workers» دکمه «Use template». حساب خود را در Account Resources و «All zones» را در Zone Resources انتخاب و توکن را بسازید. [صفحه API Tokens (لینک مستقیم)](https://dash.cloudflare.com/profile/api-tokens)
3. در صفحه «کلادفلر» توکن را بچسبانید و «ذخیره و بررسی توکن» را بزنید؛ Account ID خودکار پیدا می‌شود.

5. «عیب‌یابی اتصال» را بزنید تا مطمئن شوید کلادفلر به سایت شما دسترسی دارد (برای سایت لوکال حالت «معکوس» خودکار انتخاب می‌شود).

**رفع مشکل**

- **Authentication error (10000)** — توکن دسترسی Workers Scripts یا KV را ندارد؛ از قالب «Edit Cloudflare Workers» استفاده کنید.
- **workers.dev subdomain** — یک‌بار بخش Workers & Pages را در داشبورد کلادفلر باز کنید تا زیردامنه workers.dev ساخته شود، سپس دوباره مستقر کنید.
- **workers.dev از سرور در دسترس نیست** — در کلادفلر یک Custom Domain به ورکر وصل کنید و آن را در «دامنه اختصاصی ورکر» وارد کنید.

**مستندات رسمی:** [ساخت توکن API](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/) · [پیدا کردن Account ID](https://developers.cloudflare.com/fundamentals/account/find-account-and-zone-ids/) · [محدودیت پلن رایگان Workers](https://developers.cloudflare.com/workers/platform/pricing/)

#### Google Search Console

`بسیار مهم` `رایگان` `۱۵ دقیقه`

قلب هوش SEOlity: کلمات کلیدی واقعی، کلیک، نمایش، جایگاه، کنیبالیزیشن و کلمات کلیدی کانونی از همین داده انتخاب می‌شوند. دسترسی فقط خواندنی (webmasters.readonly) است.

**پیش‌نیازها:** حساب گوگلی که در Search Console به سایت دسترسی دارد

1. مطمئن شوید سایت در Search Console ثبت و تأیید شده است (Domain یا URL prefix). [باز کردن Search Console](https://search.google.com/search-console)
2. در Google Cloud یک پروژه جدید بسازید (نام دلخواه مثلاً SEOlity). [ساخت پروژه (لینک مستقیم)](https://console.cloud.google.com/projectcreate)
3. Google Search Console API را برای همین پروژه فعال کنید (Enable). بالای صفحه مطمئن شوید پروژه درست انتخاب شده است. [فعال‌سازی Search Console API](https://console.cloud.google.com/apis/library/searchconsole.googleapis.com)
4. صفحه رضایت OAuth را بسازید: Google Auth Platform ← Branding ← Get started. نام برنامه و ایمیل پشتیبانی را وارد کنید، Audience را External بگذارید، ایمیل تماس را بدهید و Create بزنید. [Branding (صفحه رضایت)](https://console.cloud.google.com/auth/branding)
5. مهم: در Audience روی «Publish app» بزنید تا وضعیت In production شود. در حالت Testing، اتصال هر ۷ روز قطع می‌شود. (در حالت Testing باید ایمیل خود را در Test users اضافه کنید.) [Audience](https://console.cloud.google.com/auth/audience)
6. یک OAuth client بسازید: Clients ← Create client ← Application type: Web application. [ساخت OAuth client (لینک مستقیم)](https://console.cloud.google.com/auth/clients/create) · [یا از صفحه Credentials: Create credentials ← OAuth client ID](https://console.cloud.google.com/apis/credentials)
7. در «Authorized redirect URIs» دقیقاً آدرس زیر را اضافه کنید (همان که در صفحه سرچ کنسول SEOlity نمایش داده می‌شود):

   ```
   https://YOUR-SITE/wp-admin/admin-post.php
   ```
8. Create را بزنید و Client ID و Client secret را کپی کنید (Client secret با GOCSPX- شروع می‌شود).

   ```
   xxxxxxxx.apps.googleusercontent.com  /  GOCSPX-…
   ```
9. در SEOlity به صفحه «سرچ کنسول» بروید، Client ID و Secret را ذخیره کنید، «اتصال حساب گوگل» را بزنید، حساب را انتخاب و اجازه دهید، سپس Property سایت را انتخاب کنید. داده‌ها در پس‌زمینه همگام می‌شوند.

**رفع مشکل**

- **Error 400: redirect_uri_mismatch** — آدرس Redirect در Google Cloud دقیقاً با آدرس SEOlity یکی نیست (http/https، www، اسلش آخر). آن را از همین صفحه کپی کنید. تغییرات تا چند دقیقه طول می‌کشد.
- **Google hasn’t verified this app** — برای برنامه شخصی خودتان طبیعی است: Advanced ← Go to … (unsafe) را بزنید. برنامه فقط به داده‌های شما با دسترسی خواندنی وصل می‌شود.
- **Error 403: access_denied** — برنامه در حالت Testing است و ایمیل شما Test user نیست؛ آن را اضافه کنید یا Publish app بزنید.
- **هیچ Property نمایش داده نمی‌شود** — حساب گوگلی که وصل کردید به سایت در Search Console دسترسی ندارد. در Search Console ← Settings ← Users and permissions آن را اضافه کنید.
- **اتصال بعد از یک هفته قطع شد** — برنامه در حالت Testing مانده است. Publish app بزنید و دوباره وصل شوید.
- **داده‌ها امروز را نشان نمی‌دهند** — داده‌های Search Console حدود ۲ تا ۳ روز تأخیر دارند.

**مستندات رسمی:** [راهنمای Search Console API](https://developers.google.com/webmaster-tools/v1/how-tos/authorizing) · [تنظیم صفحه رضایت OAuth](https://developers.google.com/workspace/guides/configure-oauth-consent) · [افزودن سایت به Search Console](https://support.google.com/webmasters/answer/34592)

#### Ollama (local / self-hosted)

`AI` `Free, no account` `15 min`

4. In SEOlity: Settings → AI → Provider Ollama, base URL (e.g. http://127.0.0.1:11434) and model (qwen2.5:7b); save and test.

**Troubleshooting**

- **Connection refused / timeout** — WordPress cannot reach Ollama. Shared hosting usually can’t; use a VPS or a secured public address.
- **Slow answers** — Use a smaller model or a GPU server and raise “AI timeout” in settings.

**Official docs:** [Ollama FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.md)

#### Custom API (any provider)

`AI` `Any compatible service` `5 min`

Connect any AI service with an OpenAI- or Anthropic-compatible API using exactly the settings from its documentation: DeepSeek, Groq, Mistral, Together, xAI, Perplexity, Azure OpenAI, Cloudflare Workers AI, LM Studio, vLLM, LiteLLM and similar gateways.

**You need:** An API key and the base URL from the service documentation

1. In Settings → AI open the “Custom API” card and pick your service in “Service”; the URL, format, key method and JSON mode are filled in and a link to get the key appears.
2. Service not listed? Choose “Custom” and enter the base URL from the service documentation. Examples:

   ```
   https://api.deepseek.com/v1
https://api.groq.com/openai/v1
https://generativelanguage.googleapis.com/v1beta/openai
https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/v1
https://{RESOURCE}.openai.azure.com/openai/deployments/{DEPLOYMENT}
http://localhost:1234/v1   (LM Studio)
   ```
3. “API format”: OpenAI-compatible if the docs mention /chat/completions, Anthropic-compatible for /v1/messages. A full endpoint URL also works; SEOlity detects it.
4. “How the key is sent”: most services use Bearer; Azure uses api-key, Claude-style gateways x-api-key, and some a URL parameter (e.g. key). Save the key in the API key field.
5. “Fetch models” lists the service’s models; pick one (for Azure, the deployment name).
6. Extra headers (e.g. HTTP-Referer), query parameters (e.g. api-version=2024-10-21 for Azure), the token-limit parameter and temperature are under “Advanced”. The preview shows the exact request.
7. Press “Test connection”, then “Use as AI engine”. Keep “Structured output” on Automatic: SEOlity tries json_schema, JSON mode and prompt instructions in that order and remembers what works.

**Troubleshooting**

- **404 error** — Wrong base URL — usually /v1 is missing or doubled. Compare the “Request URL” preview with the documentation.
- **401 or 403 error** — Wrong key method (e.g. Bearer instead of api-key) or the key has no credit/access.
- **response_format / json_schema error** — Automatic mode tries the next option itself; if you set it by hand choose “JSON mode” or “Instructions in the prompt only”.
- **max_tokens error** — Set the token-limit parameter to max_completion_tokens or “Do not send”.
- **Reasoning models return <think> text** — SEOlity strips the <think> part automatically; leave temperature empty.
- **Local server unreachable** — localhost means the machine WordPress runs on; for another computer use its network address.

**Official docs:** [Gemini OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai) · [Workers AI OpenAI compatibility](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/) · [Azure OpenAI reference](https://learn.microsoft.com/azure/ai-services/openai/reference)

#### ChatGPT Plus / Pro subscription (Codex)

`Subscription AI` `No API cost` `10 min`

Uses your ChatGPT plan through the Codex CLI on GitHub Actions. The login is refreshed and re-saved automatically.

**You need:** A ChatGPT Plus, Pro, Team or Business plan; A free GitHub account; Node.js on your own computer

1. Open “Subscription AI”, pick “ChatGPT Plus / Pro” and do step 1 (GitHub and repository) in one click.

   ```

   ```
3. Once, make Codex store the login in a file (macOS/Linux; the Windows command is on the page):

   ```

   ```
4. Sign in and choose “Sign in with ChatGPT”:

   ```

   ```

### Google (Search Console & speed)

#### Google Search Console

`Most important` `Free` `15 min`

The heart of SEOlity: real queries, clicks, impressions, positions, cannibalization and focus-keyword picks all come from this. Access is read-only (webmasters.readonly).

**You need:** A Google account with access to the site in Search Console

1. Make sure the site is added and verified in Search Console (Domain or URL prefix). [Open Search Console](https://search.google.com/search-console)
2. Create a new Google Cloud project (any name, e.g. SEOlity). [Create project (direct link)](https://console.cloud.google.com/projectcreate)
3. Enable the Google Search Console API for this project (check the project picker at the top). [Enable Search Console API](https://console.cloud.google.com/apis/library/searchconsole.googleapis.com)
4. Configure the OAuth consent screen: Google Auth Platform → Branding → Get started. Enter app name and support email, Audience = External, contact email, then Create. [Branding (consent screen)](https://console.cloud.google.com/auth/branding)
5. Important: in Audience click “Publish app” (In production). In Testing mode the connection expires every 7 days. (In Testing you must add your email under Test users.) [Audience](https://console.cloud.google.com/auth/audience)
6. Create an OAuth client: Clients → Create client → Application type: Web application. [Create OAuth client (direct link)](https://console.cloud.google.com/auth/clients/create) · [Or via Credentials: Create credentials → OAuth client ID](https://console.cloud.google.com/apis/credentials)
7. Under “Authorized redirect URIs” add exactly this address (also shown on SEOlity’s Search Console page):

   ```
   https://YOUR-SITE/wp-admin/admin-post.php
   ```
8. Click Create and copy the Client ID and Client secret (the secret starts with GOCSPX-).

   ```
   xxxxxxxx.apps.googleusercontent.com  /  GOCSPX-…
   ```
9. In SEOlity open “Search Console”, save the Client ID and secret, click “Connect Google account”, choose the account and allow, then pick the site property. Data syncs in the background.

**Troubleshooting**

- **Error 400: redirect_uri_mismatch** — The redirect URI in Google Cloud does not exactly match SEOlity’s (http/https, www, trailing slash). Copy it from this page. Changes can take a few minutes.
- **“Google hasn’t verified this app”** — Normal for your own app: click Advanced → Go to … (unsafe). It only reads your own data.
- **Error 403: access_denied** — The app is in Testing and your email is not a test user; add it or click Publish app.
- **No properties are listed** — The connected Google account has no access in Search Console. Add it under Settings → Users and permissions.
- **Disconnected after a week** — The app is still in Testing. Publish it and reconnect.
- **No data for today** — Search Console data lags about 2–3 days.

**Official docs:** [Search Console API guide](https://developers.google.com/webmaster-tools/v1/how-tos/authorizing) · [Configure OAuth consent](https://developers.google.com/workspace/guides/configure-oauth-consent) · [Add a property](https://support.google.com/webmasters/answer/34592)
